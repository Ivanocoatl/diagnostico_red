Bienvenida e Introducción a la CLI

Comprende la filosofía que separa a los usuarios convencionales de los administradores de sistemas avanzados.

1. Filosofía de Consola (CLI) vs. GUI

ACRÓNIMOS CLAVE

  • CLI: Command Line Interface (Interfaz de Línea de Comandos).
  • GUI: Graphical User Interface (Interfaz Gráfica de Usuario).

Explicación Teórica Profunda: La transición histórica de los sistemas operativos supuso el paso de entornos puramente textuales a sistemas gráficos. Mientras que la GUI oculta la complejidad del sistema mediante abstracciones visuales (iconos, menús desplegables), limita la velocidad, precisión y la capacidad de automatización del administrador de sistemas. La CLI se fundamenta en la transmisión de flujos de texto que se comunican directamente con el shell del sistema operativo. Esto permite la composición de comandos complejos mediante tuberías (pipelines) y el control absoluto del entorno.

Funcionamiento Interno: En el sistema operativo, la GUI actúa como un cliente del servidor gráfico que envía eventos de ratón y teclado, traduciéndolos a llamadas del sistema. En contraste, un intérprete de comandos o shell (como CMD.EXE, powershell.exe o /bin/bash) lee directamente de la entrada estándar (stdin), interpreta sintácticamente la cadena, busca el binario correspondiente en las rutas del sistema (variable PATH), genera un proceso hijo mediante fork() e exec() y devuelve los resultados a la salida estándar (stdout).

2. Comparativa: CMD vs. PowerShell vs. Bash

Windows CMD (Símbolo del Sistema)

Sintaxis: Basada en comandos internos históricos de MS-DOS.

Paradigma: Orientado a procesamiento de texto plano y ejecución secuencial de archivos por lotes (batch files).

Windows PowerShell (PS)

Sintaxis: Cmdlets estructurados bajo nomenclatura Verbo-Sustantivo (ej. Get-NetIPAddress).

Paradigma: Orientado a objetos basados en Microsoft .NET (CLR). Transmite instancias completas de objetos, evitando el parsing complejo de texto simple.

Linux Bash (Bourne Again SHell)

Sintaxis: Comandos modulares y utilidades GNU independientes.

Paradigma: Filosofía Unix de "hacer una sola cosa bien" usando texto plano como interfaz universal. Enfocado fuertemente en redirección de I/O.

3. Errores Comunes y Soluciones

Error: "El sistema no puede encontrar la ruta especificada" o "Command not found".

Causa Raíz: El ejecutable invocado no se encuentra en las rutas definidas dentro del entorno de variables globales del sistema (PATH).

Solución Paso a Paso:
  1. En Windows (CMD), verificar el contenido de %PATH% con:
    echo %PATH%
  2. En Linux (Bash), verificar $PATH con:
    echo $PATH
  3. Añadir temporal o permanentemente la ruta al ejecutable:
    Windows: set PATH=%PATH%;C:\Ruta\Al\Ejecutable
    Linux: export PATH=$PATH:/ruta/al/ejecutable

Módulo 1: Primer Contacto

Comandos fundamentales para la supervivencia en la terminal.

1. Limpieza de Terminal: cls vs. clear

Windows: cls

Acrónimo: Clear Screen.

Interactúa con la consola de Win32 borrando el búfer de caracteres del host (conhost.exe) y posicionando el cursor en las coordenadas (0,0).

Linux: clear

Consulta la base de datos terminfo para obtener las secuencias de escape ANSI correctas para el tipo de terminal activa y limpiar el área visible.

2. Listar Directorios: dir vs. ls

CMD: dir [/A] [/S] [/B]

  • /A Muestra archivos con atributos específicos (ocultos).
  • /S Lista recursivamente en subdirectorios.
  • /B Formato básico sin encabezados.

Bash: ls [-l] [-a] [-h]

  • -l Formato largo (permisos, dueño, peso, fecha).
  • -a Muestra archivos ocultos (inician con punto).
  • -h Tamaños legibles por humanos (K, M, G).

4. Copiado y Movimiento

Win: copy [/Y] [/V] | move [/Y]

/V Verifica si se escribieron bien.

Lin: cp [-r] [-i] [-u] | mv [-i] [-u]

-r Recursivo | -i Interactivo | -u Actualizar

5. Elevación de Privilegios

Windows runas: Ejecuta herramientas con permisos de otro usuario (ej. administrador).

Linux su: (Substitute User) Cambia de sesión a superusuario.

Linux sudo: Ejecuta un comando puntual como superusuario basándose en /etc/sudoers.

6. Acceso Remoto: Telnet vs. SSH

Acrónimo: SSH = Secure Shell

Explicación Teórica: Telnet transmite contraseñas en texto plano, vulnerable a rastreos (sniffing). SSH proporciona un canal cifrado (puerto TCP 22) usando criptografía de clave pública.
